# 내가왕 · Supabase + GitHub Pages

현재 공유 천하 개선판(v20)을 로그인 없이 열리는 HTML 게임으로 배포하는 저장소입니다. 모든 캐릭터 이미지, 사주 계산·해설, 천하지도, 튜토리얼, 신문·실록, 어전회의, 꾸미기, 최신 복구 링크를 포함합니다. Node 22.13 이상이 필요하며 npm 의존성 설치는 없습니다.

**이 저장소를 준비한 것만으로 Supabase 프로젝트나 공개 사이트가 생성되지는 않습니다.** 아래 최초 설정을 마치면 이후 `main`에 올린 코드가 자동 배포됩니다.

## 배포 상태와 운영 방법

Supabase 프로젝트 `ytxbpwwvawozksosgprk`에 DB와 `royal-api`를 설치했습니다. 기존 사주 앱의 테이블과 기록은 유지합니다. 데이터 테이블 `imking_worlds`, `imking_network_records`는 RLS를 켜고 브라우저의 직접 접근을 차단했으며, 서버 함수만 읽고 씁니다.

GitHub Actions는 프런트엔드를 테스트하고 GitHub Pages로 배포합니다. 공개 Project Ref만 사용하므로 GitHub Secrets, DB 비밀번호, Supabase 개인 관리 토큰을 등록할 필요가 없습니다. 서버 코드 변경은 Supabase에 별도로 배포해야 합니다. `main`에 화면 코드를 올리면 Pages가 자동 갱신됩니다.

최초 업로드에만 사용하는 `imking-source.zip`은 첫 Actions 실행에서 풀어 전체 소스 파일로 커밋하고 삭제합니다. 이후에는 저장소의 일반 소스 파일을 수정하면 됩니다. `.github/workflows/deploy.yml`이 배포를 담당합니다.

게임 API는 별도 회원가입 없이 무작위 NG1 접속 토큰으로 본인을 확인합니다. `verify_jwt=false`는 이 사용자 인증을 서버 내부에서 처리하기 위한 설정입니다. CORS는 `https://seankim2395-netizen.github.io`만 허용하고, 서버 키는 Supabase 함수의 기본 비밀 환경변수로만 사용합니다.

## 4. 기존 기록과 링크 옮기기

기존 게임에서 **복구 링크·백업 → 백업 파일 저장**을 실행합니다. 새 주소를 열고 **이미 나라가 있나요? → 백업 가져오기**로 JSON 파일을 불러온 뒤 서버 저장 완료를 확인합니다. 새 주소의 **최신 복구 링크를 다시 저장**합니다.

다른 도메인의 브라우저 저장소와 기존 Sites DB는 자동 복사되지 않습니다. 기존 주소의 복구·초대 링크는 계속 기존 서버를 가리킵니다. 새 주소에서 링크를 다시 만들어야 합니다. JSON 백업은 백업한 시점의 데이터이며, 새 서버에 저장한 뒤 만든 고정 복구 링크부터 새 서버의 최신 기록을 불러옵니다. 이전 서버의 기록은 지우지 않습니다.

## 공개 후 확인

- 로그아웃/시크릿 창에서 첫 페이지와 `assets/share-preview.jpg`가 로그인 없이 열리는지 확인합니다.
- 한 브라우저에서 인물을 만든 뒤, 같은 브라우저에서 초대 링크를 다시 열어 인물이 늘지 않는지 확인합니다.
- 복구 링크를 다른 브라우저에서 열어 저장한 최신 기록을 확인합니다. 복구 링크는 개인 접근 열쇠이므로 타인에게 보내지 않습니다.
- 두 브라우저에서 동시에 바꾸었을 때 충돌 안내가 표시되고 기존 기록이 덮어써지지 않는지 확인합니다.
- 카카오톡에 새 초대 링크를 공유합니다. 기존 정보가 남으면 [카카오 도구](https://developers.kakao.com/tool)의 URL 메타정보 관리에서 캐시 초기화 후 다시 보냅니다. OG 정보는 HTML에 미리 생성되므로 자바스크립트 실행 없이 읽을 수 있습니다.

## 현재 버전의 범위와 무료 한도

이 배포는 **초대 관계로 연결된 사람들이 같은 천하를 공유합니다.** A→B→C처럼 재초대가 이어지면 초대 계보가 공통 그래프에 추가되고, 독립해도 최초 연결은 유지됩니다. 게임은 약 10초마다 최신 활동을 확인합니다. 경배·총애·독립·꾸미기·어전회의는 익명 접속 토큰의 본인 권한을 확인한 뒤 서버에서 처리하며, 동시 활동은 리비전 비교와 재시도로 합칩니다. 가입 재시도와 활동 재전송으로 인물이나 보상이 중복되지 않도록 처리합니다.

생년월일시는 본인에게만 반환합니다. 같은 천하의 다른 사람에게는 게임 캐릭터·관계·궁합 계산용 사주 요약만 보입니다. 개인 복구 링크와 공개 초대 코드는 별개입니다. 기존 개인 서버 기록은 최초 접속 시 공유 천하로 옮기며, 과거 초대장으로 복사된 인물은 역사 기록으로 남습니다. 과거 서로 분리된 브라우저 기록을 근거 없이 자동 병합하지 않습니다. 기존 인연에게는 **개선 후 새 초대장**을 보내주세요. 이미 자신의 인물이 있는 사람은 새 초대장을 열어도 기존 천하로 돌아갑니다.

현재 한 천하는 최대 500명입니다. 초대 세대 수는 고정하지 않습니다. 그래프의 모든 사람을 기본 표시하고, 식솔은 선택하여 접을 수 있습니다. Supabase 실제 프로젝트 생성·설정 및 원격 DB 검증은 별도이며, 이 저장소만으로 계정에 프로젝트를 만들거나 유료 상품을 신청하지 않습니다.

GitHub Pages는 정적 화면을, Supabase는 저장 API와 DB를 담당합니다. 무료 한도 안에서 사용할 수 있지만 무제한은 아닙니다. 2026-10-15 확인 기준 Supabase Free는 DB 500MB, Edge Function 월 50만 호출이며 비활성 1주 후 프로젝트가 일시 정지될 수 있습니다. Free의 자동 DB 백업은 제공되지 않으므로 게임 안 백업 파일도 보관합니다. 유료 플랜 전환이나 결제 설정은 이 구성에 포함하지 않습니다.

## 로컬 검증

```bash
npm test
SITE_URL=https://YOUR_LOGIN.github.io/imking/ SUPABASE_PROJECT_REF=abcdefghijklmnopqrst npm run build
```

`dist/`만 공개 화면으로 배포합니다. `supabase/`에는 서버 코드·DB 스키마가 들어 있습니다. 원래 Sites 설정·소스 이력·사용자 DB·비밀키는 이 내보내기에 포함하지 않습니다.

공식 문서: [Supabase GitHub Actions](https://supabase.com/docs/guides/functions/examples/github-actions), [Supabase 요금](https://supabase.com/pricing), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).
